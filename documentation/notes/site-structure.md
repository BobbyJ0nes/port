# site structure

## the four layers

```
┌─────────────────────────────────────────────────────────────────┐
│  1.  STATIC SHELL  ─  port_v2/index.html, about.html, style.css │
│      hand-written. shared header (✶ بصيرة + nav), theme toggle, │
│      j/k nav, footer. design tokens live in style.css.          │
├─────────────────────────────────────────────────────────────────┤
│  2.  PROJECTS      ─  port_v2/projects/<slug>/                  │
│      each portfolio piece is a self-contained html/css/js        │
│      sub-app. tonal-gradient cards on the home page link in.    │
├─────────────────────────────────────────────────────────────────┤
│  3.  BLOG          ─  port_v2/blog/                              │
│      blog/index.html is the listing. blog/<slug>/ is one post.   │
│      ANIMUS lives at blog/animus/. interactive figures + radar.  │
├─────────────────────────────────────────────────────────────────┤
│  4.  NOTES (wiki)  ─  port_v2/notes/  (BUILD OUTPUT)             │
│      static html generated by Quartz from ../notes_quartz/.      │
│      do not edit by hand. run build-notes.js to regenerate.      │
└─────────────────────────────────────────────────────────────────┘
```

## what lives where

### `port_v2/` (root)
- `index.html` — home. work grid + featured article card.
- `about.html` — about page.
- `style.css` — design tokens (colours, type scale, layout) + shared
  components (header, nav, cards, theme toggle, j/k focus). Every
  other page imports this.
- `script.js` — theme toggle (localStorage `basaira-theme`) and j/k
  card walking.
- `serve.py` — dev server with extension-less url fallback (mirrors
  github pages).
- `build-notes.js` — wiki build orchestrator (see
  [`build-and-deploy.md`](build-and-deploy.md)).
- `CNAME` — github pages domain pin (`bobbyjones.xyz`).

### `port_v2/projects/`
- one folder per piece. self-contained. tonal gradient thumb on the
  home page card. nothing in `projects/` should import from `blog/`
  or `notes/`.

### `port_v2/blog/`
- `index.html` — the blog listing. when you add a post, also add
  a card here (see [`adding-articles.md`](adding-articles.md)).
- `<slug>/` — one post per folder. each post has its own `index.html`,
  `style.css`, and any js modules it needs. relative paths only —
  posts shouldn't import each other.

### `port_v2/notes/` (build output)
- generated. **do not edit by hand.** any change you make here will
  be wiped by the next `node build-notes.js`. edit the source in
  `../notes_quartz/content/` instead.
- contains the Quartz wiki: per-page html, asset bundles, OG images,
  the search index, sitemap, RSS feed, the `/notes/papers/` directory
  for research PDFs.

### `port_v2/documentation/notes/`
- you are here. process notes + how-to docs. pure markdown, not
  served on the live site (no .html). future-you reading these is
  the intended audience.

### `../notes_quartz/` (sibling, separate)
- the Quartz project that *generates* `notes/`. not part of this
  repo — checked in separately so you can edit content in obsidian
  without committing build artefacts. see
  [`wiki-content.md`](wiki-content.md) for the workflow.

## design tokens (the shared spine)

`style.css` defines the palette + type scale. every other CSS file —
including the article's own `blog/animus/style.css` — pulls these
custom properties through inheritance. tokens you'll touch most:

| token        | role                              |
|--------------|-----------------------------------|
| `--bg`       | page background (cream / dark)    |
| `--ink`      | primary text                      |
| `--ink-soft` | body text                         |
| `--ink-faint`| meta / mono / muted text          |
| `--accent`   | terracotta (Anthropic colour too) |
| `--accent-2` | teal (Google colour too)          |
| `--rule`     | rules + borders                   |
| `--font-ser` | Iowan Old Style (body)            |
| `--font-ar`  | Cairo (Arabic mark)               |
| `--font-mono`| Space Mono (UI / code)            |

dark theme overrides live in `:root[data-theme="dark"]` and
`@media (prefers-color-scheme: dark)`. the toggle button in the
header swaps `data-theme` and persists to `localStorage` under
`basaira-theme`.

## the article ↔ wiki bridge

inside the article (`blog/animus/`) any `<a href="/notes/...">` link
becomes a popover preview on hover (handled by `popover.js`) and a
full-page navigation on click. inside the wiki (`notes/`) every page
has a "← back to the article" link in the masthead, pointing at
`/blog/animus/`.

both sides are same-origin, so no CORS, no cross-port shenanigans.
the routing logic that makes this work:

- in the article: `popover.js` matches links whose pathname starts
  with `/notes/`. that's the wiki-link signal.
- in the wiki: Quartz's `PageTitle.tsx` component renders the
  back-link conditionally, only on pages whose slug starts with
  `animus/`. (see
  [`../../notes_quartz/quartz/components/PageTitle.tsx`](../../../notes_quartz/quartz/components/PageTitle.tsx).)

if you add a second article that has its own vault, the slug check
in `PageTitle.tsx` is the place to extend.

## why this split (and not, say, one giant Astro project)

- portfolio is hand-written html/css and that's a tenet — building it
  in a framework would lose the texture.
- the wiki is generated because writing 30+ wiki pages by hand defeats
  the point of having a vault. Quartz handles markdown → html
  competently and ships the obsidian features (popovers, backlinks,
  graph view, search) for free.
- they live in the same domain (`/notes/`) so the article and the
  wiki feel like one site to a reader, even though they're authored
  by different tools.
- only the *output* of the wiki is committed to the portfolio repo,
  so the deploy stays static + cacheable + cheap.
